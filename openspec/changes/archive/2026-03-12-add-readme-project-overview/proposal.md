## Why

目前專案已具備可執行的 Tetris 核心玩法與基本模組結構，但倉庫根目錄缺少 README，導致新讀者無法快速理解這個專案是什麼、目前做到哪裡、如何啟動與測試，也不容易從外部辨識專案的定位與開發方式。隨著專案已進入以 OpenSpec 管理變更的階段，補上 README 可以降低進入門檻，並讓後續變更有一致的對外說明基礎。

## What Changes

- 新增根目錄 `README.md`，用繁體中文說明專案目的、目前功能範圍與技術堆疊。
- 在 README 中整理專案結構，說明 `cmd`、`internal/app`、`internal/game`、`internal/input`、`internal/render` 等模組責任。
- 在 README 中補充本機開發與驗證方式，至少涵蓋執行遊戲、執行測試與 macOS 打包入口。
- 在 README 中說明目前專案聚焦於核心玩法與可測試性，不承諾尚未實作的延伸功能。

### 範圍

- 只處理 README 的建立與內容組織。
- 以目前程式碼與既有規格為準，整理可信且可驗證的專案說明。

### 非目標

- 不修改遊戲規則、輸入、渲染或測試行為。
- 不補做 README 以外的網站、Wiki 或額外文件體系。
- 不在 README 中承諾尚未存在的功能或發布流程。

## Capabilities

### New Capabilities

- `project-readme`: 定義專案 README 必須提供的定位、功能摘要、執行方式、開發入口與結構導覽

### Modified Capabilities

- 無

## Impact

- 影響範圍以文件與專案結構說明為主，主要新增根目錄 `README.md`。
- 不影響既有 Go API、遊戲核心規則、輸入處理、渲染流程或外部依賴。
- 需要檢查 README 內容與現有 `Makefile`、OpenSpec 規格及目前程式行為是否一致。

## 工程目標

- 讓第一次進入倉庫的開發者能在數分鐘內理解專案定位與開發入口。
- 建立與目前程式碼一致的文件基線，避免 README 成為過時說明。

## 玩家目標

- 玩家不會直接透過這次變更得到新功能，但未來下載或查看專案的人能更清楚知道這是一個什麼樣的 Tetris 實作，以及目前支援哪些玩法。

## 風險

- README 若描述超出當前實作，會立即造成文件與實際行為脫節。
- README 若只重述檔案名稱、缺少執行與驗證入口，仍無法有效降低新讀者理解成本。

## 驗證方式

- 人工檢查 README 是否涵蓋專案定位、功能摘要、執行方式、測試方式與模組結構。
- 逐項對照 README 與現有 `Makefile`、OpenSpec 規格及程式入口，確認沒有描述不存在的功能或錯誤命令。
