## ADDED Requirements

### Requirement: 生產程式碼 MUST 不保留無引用的核心代碼
系統的生產程式碼 MUST 移除未被正式執行路徑或測試用途引用的型別、函式、方法、欄位、常數與設定值。若某段代碼看似未使用但實際承擔近期需求、測試支撐或明確文件化的責任，則必須保留並可被清楚辨識其用途。

#### Scenario: 移除未被任何路徑使用的設定欄位
- **WHEN** 某個設定欄位在 `cmd/tetris`、`internal/app`、`internal/game`、`internal/input`、`internal/render` 與測試中都沒有有效讀取或寫入用途
- **THEN** 該欄位會自正式程式碼中移除，而不是以註解、保留空值或占位邏輯繼續存在

#### Scenario: 保留具明確責任的低頻代碼
- **WHEN** 某段代碼雖未出現在主要遊玩熱路徑，但被測試、啟動流程或已文件化的近期需求所依賴
- **THEN** 系統會保留該段代碼，並讓其用途可被呼叫點、命名或註解清楚辨識

### Requirement: 清理後的專案 MUST 維持既有玩法契約與可驗證性
在移除未使用代碼後，系統 MUST 維持既有 `playable-core-loop` 所定義的核心玩法結果，且專案仍必須可格式化、可建置並可通過現有自動化驗證。清理不得以破壞輸入處理、遊戲更新、渲染顯示或測試可重現性作為代價。

#### Scenario: 清理後通過自動驗證
- **WHEN** 完成未使用代碼清理後執行專案標準格式化與測試流程
- **THEN** 專案仍可成功完成 `gofmt` 與 `go test ./...`，不會因刪除必要結構而失敗

#### Scenario: 清理後維持玩家流程
- **WHEN** 玩家在清理後啟動遊戲並執行移動、旋轉、加速下落、暫停、重新開始與遊戲結束流程
- **THEN** 玩家可見行為與清理前一致，不會因內部代碼精簡而出現功能缺失或狀態錯亂
